# 최근 104회 최다 출현 전환

## 결정: 2026-10-23

사용자 요청에 따라 다음 신규 추천부터 최근 104회 최다 출현 방식을 실험 적용한다. 적중률 향상이 입증되었다는 결정이 아니며 기존 방식과의 실제 사전 성적 비교를 계속한다.

- 최초 적용: 1248회(2026-10-31 추첨), 1247회 공식 결과가 정상 갱신된 뒤 생성.
- 보존: 이미 발행한 1247회 `20, 25, 36, 38, 40, 44`, 생성 시각과 모든 과거 기록.
- 엔진: `weekly-hot104-v3`. 사용자가 보는 추천은 매주 6개 번호 1세트뿐이다.
- 앱 캐시: v16. 설정 저장 키는 바꾸지 않아 통계 표시 범위 설정을 유지한다.

## 선택 규칙

목표 회차 N에 대해 N-104~N-1의 본번호 출현 횟수를 집계한다. 횟수가 많은 순서로 6개를 선택하며 동률이면 작은 번호를 우선한다. 최종 번호는 오름차순으로 표시한다. 보너스 번호, 더 오래된 회차, 미래 회차, 지난 추천 성적은 선택에 넣지 않는다. 화면의 통계 범위 설정과 무관하게 추천 기간은 104회다.

정확히 104개 연속 회차가 필요하다. 기간 부족·중간 누락·중복·잘못된 본번호는 실패 처리하고 임의 방식으로 대체하지 않는다. 순위가 유지되면 다른 주에도 같은 번호를 추천할 수 있다. 홀짝이나 합계는 표시용 설명이며 번호 선택 조건이 아니다.

## 기존 방식과 비교

새 추천을 만들 때 원래 `weekly-single-random-v2`도 동일한 기준 회차로 실행해 같은 생성 시각의 `comparison` 필드에 저장한다. 이는 비교용 기록으로 추가 구매 추천이 아니다. 이후 같은 실제 당첨번호로 두 기록을 평가한다.

화면은 현재 보관된 최근 52개 회차 기록에서 유효한 평가 쌍만 사용한다. 본번호 평균 적중 수, 0개 적중 비율, 3개 이상 비율, 회차별 적중 수와 승·무·패를 표시한다. 0개 적중도 반드시 분모에 포함하고 평가가 없으면 `-`로 표시한다. 현재 파일은 무기한 누적 저장소가 아니며 52개를 벗어난 기록은 Git 이력에 남는다. 이전 v2 회차에는 비교를 사후 추가하지 않는다.

Python 연구 후보 `hot-104`의 동률은 고정 난수 규칙이다. v3의 번호순 동률과 다르므로 과거 4회 등의 연구 성적을 새 엔진 성적이라고 표시하거나 합산하지 않는다. 기존 52개 후보 연구와 `current` v2 기준은 별도 원장에서 그대로 유지한다.

## 구조와 검증

- `hot104-engine.js`: 빈도 선택과 저장 설정 검증.
- `recommendation-comparison.js`: 원래 v2 동시 생성·검증·동일 회차 성적 요약.
- `weekly-cycle.js`: 엔진 전환, 이미 생성된 번호 보존, 평가와 52회 보관.
- `strategy-comparison.js`: 대기/평가 완료 화면. core 계산과 DOM 표시를 분리한다.
- 테스트: 정확한 기간, 미래·보너스 제외, 동률 순서, 누락 거부, 1247회 보존, 1248회 전환, 재실행 불변성, 같은 결과로 평가, 번호·시각·설정 변조 거부, 과거 비교 소급 추가 거부.
- PWA: 새 모듈을 v16 앱 셸 캐시에 포함하고 구버전 진입 URL의 오프라인 복구 테스트를 유지한다.

## 제한과 후속 확인

공정하고 독립적인 추첨에서 과거 빈도만으로 다음 당첨 확률이 높아진다고 보장할 수 없다. 이 변경은 요청한 규칙의 적용이며 개선 증명은 아니다. 1248회 결과부터 실제 비교가 쌓이고 아직 평가 전인 상태를 개선 수치로 표현하지 않는다. 매주 기존 자동 데이터 갱신이 생성·평가를 수행하므로 휴대폰에서 번호를 다시 만들 필요는 없다.

성적이 좋아지거나 나빠져도 자동 재추첨, 기간 최적화, 엔진 교체를 하지 않는다. 다음 규칙 변경 시에는 새 버전과 적용 회차를 명시하고 그 전에 고정한 기록을 보존해야 한다.
