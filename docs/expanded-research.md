# Expanded Recommendation Research

## Scope and Protocol

2026-09-20 재요청에 따라 기존 8개 단순 규칙 비교를 확장했다. 목표는 반복되는 예측 신호를 찾고 적중 수를 높이거나 0개 적중을 줄이는 것이다. 결과에 맞춰 실험을 중단하거나 유리한 번호만 골라 개선으로 보고하지 않는다.

실험 조건은 `scripts/research/protocol.json`에 고정했다. 과거 결과는 이미 관측된 데이터이므로 아래 후반 구간도 완전히 봉인된 미관측 시험이라고 주장하지 않는다. 모든 모델은 각 예측 시점 이전 데이터만 사용한다.

| 구분 | 내용 |
| --- | --- |
| 준비 | 1~260회 |
| 후보 선택 | 261~982회, 722회 |
| 후반 확인 | 983~1242회, 260회 고정 |
| 실제 사전 검증 | 1243회부터 생성 시각과 번호를 고정 보관 |
| 본번호만 평가 | 매회 6개 중 일치 수, 0개 비율, 3개 이상 비율 |
| 실사용 추천 | 기존 1세트 유지, 실험 번호와 별도 |

## Models

기존 방식 1개와 후보 52개를 비교한다. 후보 수를 늘리는 것은 실사용 추천이나 구매 세트 수를 늘리는 것이 아니다.

- 통계 32개: 13/26/52/104/260/520/전체 기간의 최다·최소 출현 14개, 지수감쇠 빈도 5개, 번호 간 1회차 전이 확률 6개, 미출현 간격별 조건부 출현 확률 3개, 유사한 직전 추첨을 찾는 이웃 기반 모델 4개.
- 학습 14개: 규제 강도와 훈련 구간을 달리한 로지스틱 회귀 6개, 히스토그램 그래디언트 부스팅 4개, Extra Trees 4개.
- 적응형 6개: 직전 156/260회 성적만으로 평균 적중 최상위 후보 선택, 1개 이상 적중 최상위 후보 선택, 평균 적중 상위 5개 후보 확률 평균. 최소 52회 이전 예측 성적이 쌓인 뒤 선택하며 그전에는 동일 확률을 사용한다.

학습 입력은 여러 기간의 과거 빈도, 지수감쇠 빈도, 직전 1~10회 출현 여부, 미출현 간격, 빈도 변화, 번호 식별값이다. 한 회차의 45개 번호 행을 함께 훈련/평가 구간으로 나눠 같은 회차 일부가 양쪽에 섞이지 않게 한다. 26회마다 과거 자료로 재학습하며 구간 중간의 입력 통계도 각 시점까지 알려진 값만 사용한다.

전처리 StandardScaler는 훈련 자료에서만 적합한다. 트리의 무작위 조기 종료용 검증 분할은 사용하지 않는다. 미래 값 차단과 인위적인 전이 패턴 탐지를 자동 테스트한다. 모델 구현은 직접 만든 최적화기가 아닌 고정 버전 scikit-learn을 사용한다.

## Evidence

후보 선택은 선행 구간 평균 적중, 0개 비율, ID 순서로 수행한다. 후반 최고 성적은 별도의 사후 탐색값으로 표시해 선택된 후보와 구분한다. 52개 신규 후보와 앞서 비교한 8개를 포함한 60회 비교를 기준으로 p값을 Bonferroni 보정한다.

과거 검토 조건은 두 구간 각각 평균 적중 0.9 이상, 0개 적중 비율이 이론값보다 5%p 이상 낮음, 3개 이상 비율이 이론값 이상, 보정 p값 0.05 이하다. p값은 초기하분포를 회차 수만큼 합성한 정확한 귀무분포를 사용한다. 13회 길이의 이동 블록 부트스트랩 10,000회로 현재 방식과의 평균 차이 구간을 추가한다. 이 구간은 설명용이며 여러 후보에 대한 동시 유의성을 보장하지 않는다.

균등 확률의 Brier 점수와 각 모델의 확률 예측 오차도 비교한다. 단순히 출현하지 않을 것이라고 예측해 높은 분류 정확도를 얻는 방식은 사용하지 않는다.

별도로 균등한 6/45 이력 2,000개를 생성해 전체 빈도 편차, 번호 45개 중 최대 편차, 번호 쌍 990개 중 최대 편차, 1~12회 지연과 45개 번호 중 최대 자기상관을 검사한다. 각 검사는 내부 최대값 선택을 모의실험으로 보정하고, 네 가지 진단 사이에서도 보정한다. 과거 분포의 이상이 발견되더라도 곧바로 다음 회차 예측 능력으로 해석하지 않는다.

- 0개 비율이 가장 낮았던 후보는 현재보다 0개 적중이 10회 적었지만, 3개 이상은 3회 대 6회로 줄었다. 한 지표만 골라 전체 적중률이 개선됐다고 주장하지 않는다.

- 모든 후보의 후반 보정 p값은 1.0이며, 두 구간의 사전 검토 조건을 모두 통과한 후보는 0개다. 후보 52개 모두 후반 Brier 점수가 균등 확률의 0.115556보다 나빴다(낮을수록 좋음).
- 빈도 총편차, 최대 번호 편차, 최대 번호 쌍 편차, 최대 지연 상관의 모의실험 p값은 각각 0.871, 0.471, 0.605, 0.257이었다. 네 검정 보정 후 모두 1.0이다. 이는 검사한 형태의 편향을 발견하지 못했다는 뜻이지 완전한 무작위성의 증명이 아니다.

실사용 엔진과 이미 발행한 1243회 추천 `3, 5, 11, 27, 30, 39`는 보존했다. 이번 변경은 탐색 범위와 검증의 개선이며 적중률 자체를 높인 엔진 교체가 아니다. 과거에 이미 본 결과에서 더 좋은 설정을 반복 탐색하는 것만으로 증거를 만들지 않고, 다음 절의 실제 사전 검증으로 이어간다.

### Platform Sensitivity

macOS에서 두 번 실행한 결과는 같았지만, 같은 패키지 버전과 seed의 GitHub Linux 실행에서는 학습/적응형 후보 13개의 후반 적중 히스토그램이 달랐다. 선행 선택 모델은 두 환경 모두 `logistic-all-0.1`이었고 선행 평균은 0.856(macOS) 대 0.859(Linux)로 달랐다. 후반 최고 후보, 표의 후반 성적, 진단 결과와 미채택 결론은 동일했다.

가장 큰 후반 평균 차이는 `adaptive-any-hit-156`의 0.758 대 0.685였다. 학습의 수치 차이가 번호 순위와 이후 적응형 선택에 증폭될 수 있으므로 이를 단순한 표시 반올림 차이로 취급하지 않는다. 비트 단위 교차 플랫폼 재현성을 주장하지 않으며, 이 민감성 자체도 해당 모델을 실사용에 채택하기 전 해결해야 할 제한이다. 최초 macOS 보고서는 구현 커밋 `50c657e`, Linux 보고서는 자동 생성 커밋 `ea9e406`에 각각 남아 있다. 향후 공식 누적은 GitHub의 고정 패키지 환경에서 수행하되 실제 평가의 기준은 재계산한 과거 값이 아니라 최초 발행한 사전 원장이다.

## Prospective Record

`data/research-shadow-records.json`은 실제 당첨이 발표되기 전에 후보별 다음 번호를 보관한다. 각 기록에 생성 시각, 목표 회차/날짜, 입력 이력 해시, 코드/프로토콜 해시, 번호 해시를 저장한다. 같은 회차를 재실행해도 이미 저장한 예측을 교체하지 않는다. 놓친 과거 회차는 사후 생성하지 않는다.

매주 당첨 결과가 들어오면 이미 보관된 예측만 평가한다. 반복 확인으로 우연한 성공을 채택하지 않도록 고정된 지수 기울기 0.1/0.25/0.5의 likelihood-ratio martingale을 동일 가중치로 혼합한 e-process를 사용한다.

`E_n = mean_lambda exp(lambda * sum(hits) - n * log(sum_k P_null(k) * exp(lambda*k))))`

공정·독립 추첨 귀무가설에서 한 회차의 조건부 적중 분포는 과거 정보로 고른 어떤 고정 6개 세트에도 동일하다. 따라서 이 e-process는 과거 성적에 따라 후보의 선택이 바뀌더라도, 추첨 전에 번호를 고정하면 적용할 수 있다. 후보 수 52개에 대해 e값 52/0.05=1,040, 최소 104회 실제 사전 평가, 평균/0개/3개 이상 실용 기준을 함께 요구한다. 반복 평가 시점을 선택해도 오류율을 통제하기 위한 조건이며, 성공이나 특정 시점의 개선을 보장하지 않는다. 기준에 도달해도 엔진은 자동 교체하지 않고 검토 대상으로 표시한다.

프로토콜의 후보 목록이나 기준을 변경할 때는 새 프로토콜과 별도 원장을 사용해야 한다. 과거 기록의 생성 시각·예측값을 고쳐 검증 실적을 늘리지 않는다. 여기의 오류율은 고정된 이번 후보 집합에 대한 것이다. 여러 새 프로토콜을 반복 시작한다면 전체 연구에 걸친 오류 예산을 별도로 설계해야 하며 매번 0.05를 새로 쓰고 전체 오류율도 0.05라고 주장하지 않는다.

첫 원장은 2026-09-20에 1243회 후보 52개와 현재 방식 1개의 번호를 고정했다. 현재 실제 사전 평가 완료는 0회다. 104회는 최소 관측 기준일 뿐 충분한 검정력이나 2년 뒤 성공을 보장하는 일정이 아니다. 생성 시각과 자체 해시만으로 외부 공증을 대신할 수 없으므로 추첨 전 GitHub 커밋으로도 기록을 남긴다. 원장 코드 해시는 해당 번호가 처음 생성된 시점의 해시이며, 후속 검증 코드가 바뀌어도 기존 원장의 해시는 유지한다.

## Reproduction

```bash
python3.12 -m venv .venv-research
source .venv-research/bin/activate
python -m pip install -r scripts/research/requirements.txt
npm run research:test
npm run research
npm run check
```

당첨 데이터까지 갱신할 때는 `npm run update:all`을 실행한다. 기존 `npm run update:data`는 당첨/추천 및 기본 분석까지만 갱신하는 가벼운 경로다. GitHub 주간 워크플로는 이 경로의 검증·배포를 먼저 완료한 뒤 확장 연구를 검사·실행·배포한다. 연구가 실패해도 기존 앱의 주간 갱신은 이미 완료된 상태다. 앱 자체는 계속 정적 PWA이며 Python은 연구용 오프라인/CI 도구에만 필요하다.

생성물은 `data/research-analysis.json/js`, `data/research-shadow-records.json`이다. 전체 후보별 수치, 진단 결과, 버전과 해시는 생성 보고서에 남긴다.

최초 분석은 NumPy 2.5.3, SciPy 1.18.1, scikit-learn 1.9.1로 수행했다. macOS에서 구버전 SciPy 로딩 오류 및 구버전 NumPy의 행렬 연산 경고를 확인해 호환 버전을 고정했고, 해당 오류가 있었던 실행의 결과는 사용하지 않았다. RuntimeWarning을 실패로 처리하며 미래 데이터 차단, 알려진 전이 패턴 회수, 원장 보존, 등록 이전/마감 이후/입력 길이 불일치 거부, e값 귀무 기대값을 테스트한다. 위 플랫폼 민감성은 별도 한계로 공개하며 이미 발행한 사전 예측은 재계산값으로 교체하지 않는다.

한계: 당첨번호만을 입력으로 사용했다. 이 분석은 가능한 모든 물리적 편향·비정상성·모델을 배제하지 않으며, 개선 근거가 반드시 존재한다고 약속할 수 없다. 연구를 계속하는 방식은 고정된 후보 전체의 사전 기록과 실제 결과를 누적하는 것이며, 유리한 한 주가 나올 때까지 기준이나 seed를 바꾸는 방식이 아니다.
