기존 통계·머신러닝 연구 52개는 그대로 보존했다. 이번 연구는 번호 조합의 분산, 보너스 전이, 번호별 미출현 간격, 회차 주기, 최근 성적에 따른 선택을 추가 조사한다. 빈도 후보 일부는 운영 v3와 같은 동률 규칙으로 재검증한 것이므로 모두 새로운 독립 아이디어라고 세지 않는다. 앱의 1247회 확정 번호, 1248회부터 적용할 v3, 기존 비교 기록과 PWA v16은 변경하지 않았다.

## 검증 설계

1. 최초 260회를 준비하고 261~1246회 986회에서 다음 회차를 순차 예측한다. 보너스는 입력 가설에만 쓰며 적중 수에는 본번호만 포함한다.
2. 최근 987~1246회 260회를 주요 과거 비교로 사용한다. 최근 104회, 비중첩 260회 블록, 전체 결과도 함께 공개한다. 모두 이미 관측한 자료이며 봉인된 미관측 시험이 아니다.
3. 적응형 후보는 521회부터 과거 성적으로 선택한다. 그 이전에는 hot104를 사용하므로 실제 선택 기간 521~1246회 726회도 별도로 표시한다. 목표·미래 데이터와 미래 보너스를 바꿔도 해당 예측이 바뀌지 않는지 테스트한다.
4. 평균 적중, 0개 비율, 3개 이상 비율을 각각 검사한다. 평균은 정확한 초기하분포 합성, 두 비율은 정확한 이항 꼬리확률이다. 기존 대안 60개와 이번 40개, 지표 3개를 포함한 계수 300으로 보정한다. 이는 이번 명시적 비교의 보정이지 모든 과거 탐색 전체를 사전 등록한 시험으로 바꾸는 장치가 아니다.
5. 평균 +0.1개, 0개 비율 -5%p, 3개 이상 비율 +1%p 중 해당 목표와 보정 p값 0.05 이하를 요구한다. 다른 두 지표는 관측값이 이론값보다 나쁘지 않아야 한다. 이는 실용적 안전 조건이며 다른 지표의 비열등성을 통계적으로 입증한 것은 아니다.
6. 기존 v2 대비 차이는 13회 블록을 재표집한 5,000회 부트스트랩 구간도 제시한다. 후보 전체의 동시 신뢰구간이 아닌 설명용 수치다.

선택용 과거 성적과 이후 평가를 분리하는 이유는 결과에 맞춘 설정 선택이 성능을 부풀릴 수 있기 때문이다. [scikit-learn의 중첩 검증 설명](https://scikit-learn.org/stable/auto_examples/model_selection/plot_nested_cross_validation_iris.html), [데이터 누출 방지 지침](https://scikit-learn.org/stable/common_pitfalls.html)을 참고했다.

## 우연·동률·패턴 진단

실제와 같은 길이 1,246회의 **완전 균등 가상 이력 100개**에도 동일한 40개 후보, 적응형 선택, 최근 260회 평가를 적용했다. 97개 이력에서 하나 이상의 보정 전 p<0.05가 나왔고, 보정 후에는 2개 이력만 남았다. 무작위 데이터의 사후 최고 평균 중앙값도 0.896개로 실제 최고 0.862개보다 높았다. 가상 최고값의 95% 범위는 0.860~0.962개, 실제 최고값에 대한 탐색용 몬테카를로 p값은 0.970이다. 유한한 대조 실험이며 후보 설계 자체를 사후에 했다는 한계를 없애지 않는다.

## 다음 검증과 개선 방향

추가 조사 가설 중 보너스 전이, 26회 주기, 커버리지는 구체적인 비교 대상이지만 검증된 추천 방식은 아니다. 이 셋만 남기고 실패 후보를 지우지 않고 **40개 전체**를 같은 조건으로 추적한다. 현재 실사용 hot104와 기존 v2도 별도로 비교하며 추천을 추가 발행하거나 구매량을 늘리지 않는다.

새 `pattern-research-v1`은 1248회(2026-10-31)부터 추첨 전 번호를 `data/deep-research-shadow-records.json`에 고정한다. 1247회는 채워 넣지 않는다. 1246회 데이터 시점의 원장은 비어 있으며 실제 평가 완료는 0회다. 이후 GitHub 주간 작업에서 기존 원장 검증기를 재사용해 생성 시각·번호·해시를 보존하고, 이미 고정한 예측만 평가한다. 놓친 회차를 사후 생성하지 않으며 운영 엔진을 자동 교체하지 않는다.

평균, 1개 이상, 3개 이상을 각각 `f(k)=k`, `1[k>0]`, `1[k>=3]`으로 두고 혼합 e-process를 계산한다.

`E_n(f) = mean_lambda exp(lambda * sum(f(hits)) - n * log(sum_k P_null(k) * exp(lambda*f(k)))))`

기울기는 0.1/0.25/0.5로 고정한다. 공정·독립 추첨에서 추첨 전에 정한 각 세트의 조건부 적중 분포를 사용하므로 반복 확인과 과거에 따른 적응형 선택을 허용한다. 새 연구의 오류 예산 0.01을 후보 40개와 목표 3개에 배분해 **각 목표 e값 12,000 이상**, 실제 사전 평가 최소 104회와 해당 실용 조건을 함께 요구한다. 기준을 넘겨도 바로 배포하지 않고 추가 검토한다.

이전 연구의 0.05를 초기화하지 않는다. 두 사전 연구 전체의 단순 합집합 오류 상한은 0.05+0.01=0.06이며 전체가 0.05라고 주장하지 않는다. 추가 프로토콜을 계속 열려면 새 오류 예산 설계가 필요하다. 과거의 보정 p값은 이 미래 오류 통제에 합산하는 증거가 아니다.

104회는 성공 기한이 아니다. 가상 IID 적중 분포를 지수적으로 기울인 계산에서, 평균이 실제 0.9개라도 계수 300으로 보정한 평균 단독 검정의 검출력은 104회 0.96%, 260회 6.10%, 986회 63.45%였다. 평균 1.0개라면 각각 13.62%, 65.45%, 100%에 가깝다. 이는 가정에 따른 고정 표본 검정력이지 미래 e-process의 성공 확률이나 모든 실용 조건의 통과 확률이 아니다. 작은 개선의 미검출과 개선이 없다는 증명은 구분한다.

더 조사할 수 있는 독립 정보는 추출 순서·기계·공 세트 등이다. 먼저 공식 출처, 완전성, 판매 마감 전 입수 가능성을 확인해야 한다. 추첨이 끝난 뒤에만 알게 되는 기계·공 정보를 과거 모델에 넣어 성능을 높이는 것은 실제 예측 개선으로 인정하지 않는다. 현재 데이터에는 이 정보가 없으며 확보했다고 주장하지 않는다.

외부 교차 확인으로 한국 로또 1,234회를 다룬 [Minseong Kim의 2026년 프리프린트 초록](https://papers.ssrn.com/sol3/papers.cfm?abstract_id=6776098)도 확인했다. 그 초록은 검사한 hot/cold·기간별 신호에서 반복 가능한 이득을 확인하지 못했다고 요약한다. 전문·코드의 독립 재현이나 동료 심사 확인을 한 것은 아니며 이번 수치의 근거는 위 자체 실행 결과다.

## 재현과 파일 책임

기존 연구와 같은 Python 3.12 및 `scripts/research/requirements.txt`의 고정 패키지를 사용한다.

```bash
npm run research:patterns:test
npm run research:patterns
npm run research:sources
npm run check
```

`research:sources`만 외부 공식 API 조회를 요구한다. 나머지는 체크인된 당첨 자료로 실행한다. 산출물은 `data/deep-research-analysis.json`, 별도 사전 원장, 공식 표본 감사 JSON이다. `--output-dir /tmp/npick-pattern-reproduction`으로 다른 폴더에서 재현할 때도 기존 원장을 입력으로 가져와 이미 고정한 번호를 보존한다. 빈 원장으로 검증 시계를 재시작하지 않는다.

모델, 과거 평가·대조·검정력, 분포 진단, 미래 증거 집계를 각각 `pattern_models.py`, `pattern_evaluation.py`, `pattern_diagnostics.py`, `pattern_prospective.py`로 분리했다. `run.py`만 파일 입출력과 전체 실행을 조율한다. 코드·프로토콜·입력 해시와 패키지 버전을 보고서에 남긴다. `source-audit.mjs`는 데이터 출처 표본 검사만 수행한다.

`npm run update:all`은 기본 갱신과 두 연구를 실행한다. CI는 기존 주간 추천 배포를 먼저 완료하고 기존 연구 뒤에 새 연구를 실행·검증·커밋·배포한다. 연구 결과는 앱 런타임에서 불러오지 않고 새 서버도 추가하지 않는다. 새 분석이 실패하더라도 이미 배포된 기본 추천을 되돌리지는 않으며 작업 실패는 감추지 않는다.
